# 2026-09-20 — program roadmap: «Питомец Финни»

> Это **оркестровый** план программы, не implementation plan Superpowers.  
> Код по `superpowers:writing-plans` + TDD — **отдельным** файлом на каждую подсистему после ок на design и SA.  
> Исполнение: `subagent-driven-development` (рекомендация на длинной экономике) или `executing-plans` (нативно в сессии). Иван выбирает на handoff.

**Goal:** Сдать обучающий Android-прототип с игровыми монетами, питомцем и демо Приложения А, не связывая экономику с чем-либо вне игры.

**Architecture:** Чистый домен экономики → контент JSON → локальный профиль → UI. Первый код — только домен.

**Tech Stack:** Дефолт Flutter; смена до старта writing-plans №1.

**Spec:** `docs/superpowers/specs/2026-09-20-finni-core-design.md` и SA `docs/work/product/FINNI_CORE_SA_SPEC.md`

## Global Constraints

- Только вымышленные игровые монеты; educational-currency.
- Ветка `Ivan_DevStand`; не создавать до первого implementation plan; не main.
- Коммиты: согласие «исполняй план» = коммиты в свою ветку по шагам. Push — отдельный вопрос git-collaboration.
- Нет продакшн-кода без красного теста (test-driven-development).
- Worktree только от `Ivan_DevStand`, без второй публичной ветки.
- Не merge в main через finishing-a-development-branch.

## Review Focus (дыры, которые фазы P3–P6 должны закрыть тестами или демо)

- Покупка ровно на весь баланс — проходит, ноль допустим, минус нет.
- Двойной тап покупки не списывает дважды.
- Сброс демо не оставляет хвосты прошлого профиля.
- Тексты ошибки понятны без цвета как единственного сигнала.
- Задание с «неправильным» выбором всё равно даёт объяснение и путь восстановления.

## Почему старый P2 «сразу слои + UI-скелет» слабый

Superpowers: план должен давать работающее проверяемое ПО; шаг = 2–5 минут с тестом. Скелет приложения без красных тестов домена — это код вперёд. **Первый implementation plan — только economy.**

YAGNI: не закладывать iOS, сервер, ИИ, мультиплеер в план №1.
