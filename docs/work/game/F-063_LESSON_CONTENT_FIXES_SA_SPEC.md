## 3. Бизнес-требования

| ID | Требование | Приоритет |
|----|------------|-----------|
| BR-01 | «Закрыть еду» → «Купить еду»; «нужное закрывают» → «нужное покупают» | Must |
| BR-02 | В уроках «наклейка» заменена на понятную хотелку — «мороженое»; в магазине «Наклейки» — с пояснением «Наклейки со зверятами» | Must |
| BR-03 | Первый урок: карточка «Главное правило» — **до** шага «собери», а не после; финальная карточка — «Молодец!» | Must |
| BR-04 | Шаг «собери» (order) получает сцену: эмодзи и короткую ситуацию, к которой относится правило | Must |
| BR-05 | Шаг «собери» — почти готовое предложение с 1–2 пропусками: часть слов уже стоит, ребёнок вставляет недостающие из 2–3 плиток | Must |
| BR-06 | Проверка рецепта урока (`validate()`) принимает новые поля | Must |

## 8. API

```json
{"type": "order", "scene": {"emoji": "🛒", "text": "Аня идёт в магазин…"},
 "prompt": "Вставь пропущенные слова", "tiles": ["Сначала", "нужное,", "потом", "хотелки"],
 "given": [0, 2], "extra": ["сразу"], "why": "…", "hint": "…"}
```

`given` — индексы слов, которые уже стоят на месте; ребёнок заполняет остальные.

## 9. Тестирование

`lesson_test` / `lesson_helpers`: прохождение шага с пропусками, ошибочная плитка; `content_test`: `given` в пределах `tiles`.
