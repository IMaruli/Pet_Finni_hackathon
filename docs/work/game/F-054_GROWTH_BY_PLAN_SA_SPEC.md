# Рост учитывает траты по плану — системная спецификация (SA)

| Поле | Значение |
|------|----------|
| **ID** | F-054 |
| **Назначение** | Хороший период засчитывается, только если нужное закрыто, хотелки не превысили план и что-то отложено (ТЗ 2.5.10) |
| **Репозиторий** | `Pet_Finni_hackathon` |
| **Источник** | Полный аудит по ТЗ 2026-09-25 (`product/TZ_FULL_AUDIT.md`); решение Егора: «по 1 пункту вноси изменения, согласование не требуется, бери 2–8» |
| **Статус** | Реализовано 2026-09-25 |
| **Связанные артефакты** | Домен экономики `ClosePeriod` (Иван), F-015 (итог дня) |

---

## 1. Требование ТЗ

2.5.10: «Развитие зависит от совокупности решений за несколько игровых периодов: удовлетворения обязательных расходов, **соответствия фактических трат составленному плану** и регулярности накоплений». Раньше третье условие не проверялось.

## 3. Бизнес-требования

| ID | Требование | Приоритет |
|----|------------|-----------|
| BR-01 | Хороший период = нужное куплено на сумму ≥ плана «Нужное» **и** на хотелки потрачено ≤ плана «Хочу» **и** отложено > 0 | Must |
| BR-02 | Итог дня показывает три условия галочками: «Нужное куплено», «Хотелки по плану», «Отложено» — ребёнок видит, почему день хороший или нет | Must |
| BR-03 | Стадия не понижается (безопасная ошибка), считаются только хорошие периоды | Must |
| BR-04 | Совет на завтра при перерасходе «Хочу» — «Держись плана…» | Must |
| BR-05 | Текст «stage.why» перечисляет все три условия | Must |
