## 1. Что это за продукт

Бесплатный **просветительский прототип Android-приложения** (готового к будущему RuStore, публикация на хакатоне не нужна). Ребёнок 7–11 лет растит виртуального питомца, а состояние и рост персонажа зависят от **финансовых решений**, а не от «покормить/погладить».

Образовательная ось — Единая рамка компетенций (раздел 6), базовый уровень НОО:

1. Доходы ≥ расходы, смысл личного/семейного бюджета.
2. Обязательное vs желаемое.
3. Покупки при ограниченном бюджете.
4. Короткая цель и регулярные откладывания.
5. Оценка своих решений («что случилось и почему»).
6. Детское приложение при участии значимого взрослого.

**Роли:** ребёнок решает сам; взрослый видит прогресс и может сбросить профиль, но не играет вместо ребёнка.

**Жёсткая граница (и после конкурса):** это обучающая платформа. Все суммы — **вымышленные игровые монеты** без стоимости вне игры. Нет обмена, нет привязки экономики к чему-либо за пределами приложения. Также нет рекламы, покупок за средства вне игры, ПДн, чатов и рейтингов с персональными данными.

## 2. Что обязательно должно быть в реализации (конкурсный каркас)

Три связанные механики, которые эксперты проверяют как отдельные, но связанные: **план бюджета → траты (нужное/желаемое) → накопления на цель**. Питомец — мотивационный слой поверх них, не замена.

| Модуль | Минимум из ТЗ |
|--------|----------------|
| Онбординг | Гость, игровое имя, 3 типа решений: обязательное / желаемое / отложить; подсказка всегда доступна |
| Питомец | Кастом внешности (≥ 9 комбинаций), имя, ≥ 3 стадии роста, обратимые состояния (настроение и т.п.) без смерти/болезни как наказания |
| Главный экран | Питомец + баланс + накопления + цель + состояние + активное задание, без сложной навигации |
| Доход | Задания и/или периодический игровой доход; каждое начисление с источником и суммой |
| Бюджет | До периода: ≥ 3 корзины; сумма ≤ доступно; план→факт после подтверждения |
| Магазин | ≥ 8 позиций, 2 типа; цена, категория, влияние на питомца; подтверждение; нельзя уйти в минус |
| Цели | ≥ 3 цели; прогресс; перевод в накопления; снятие только с отдельным подтверждением и показом ущерба цели |
| Задания | ≥ 6 штук, ≥ 3 темы (бюджет, сбережения, покупки в игре); ситуация с выбором, **не только тест**; объяснение всегда |
| Обратная связь | Что изменилось и почему; путь восстановления после ошибки |
| История | Задания, цель, итог последнего периода; короткий словарь терминов |
| Взрослый | Барьер (удержание / пример); цели продукта и прогресс без стыда; сброс/удаление профиля |
| Демо | Тестовый профиль, ≥ 5 периодов подряд без календарных ожиданий, сброс к исходным данным |
| Контент | Новое задание без переписывания ядра |
| Техника | Android 8+, портрет от 360 dp, офлайн-цикл, локальное хранение, APK, старт ≤ 5 с, отклик ≤ 1 с, тесты экономики |
| Сдача | README, архитектура, формулы экономики, карта контента, матрица требований, тест-кейсы, лицензии ассетов, черновик карточки RuStore, живое демо Приложения А + запасное видео ≤ 3 мин |

**Не компенсирует обязательное:** ИИ, облако, iOS, веб-кабинет родителя, «красивый тамагочи без бюджета».

Сквозной демо-путь (Приложение А): установка → профиль → питомец → стартовый бюджет → план → задание+доход → обязательная и необязательная покупка (+ отказ при нехватке) → цель и пополнение → (обратная связь) → следующий период и рост → перезапуск с сохранением → раздел взрослого и сброс.

## 3. Разведка конкурентов (упор сейчас)

Полного клона ТЗ на рынке нет: либо **квизы без игровой экономики**, либо **тамагочи без бюджета**, либо **трекеры копилки без плана vs факта**, либо западные pet+budget с облаком, подпиской и смешением учёбы с домашним учётом вне игры.

### 3.1. Карта игроков

| Продукт | Что сильного | Где проигрывает ТЗ / нам |
|---------|--------------|---------------------------|
| **Финзнайка 6+** | Тысячи заданий, школьный контур, аватар/турнирная валюта | Квиз/тест, слабо связанный цикл «план–факт–накопления–питомец». ТЗ прямо штрафует «только выбор из вариантов». |
| **Три Кота: Финансы** (RuStore) | Знакомый IP, темы бюджета/целей, низкий порог | Другой возраст/тон, нет обязательного питомца как следствия бюджета, риск «нажми правильную кнопку». |
| **Игровые копилки** («Копилка: коплю на мечту» и аналоги) | Визуал цели, трекер суммы | Нет обязательных/необязательных трат, нет плана vs факта, нет учебной обратной связи, часто не 7–11. |
| **Tam Tam / виртуальные питомцы** | Ежедневный заход, кастом, эмоции | Уход за питомцем ≠ учебное решение о бюджете. Стрики и «пропустил — наказан» этически спорны (тревога за питомца). |
| **Monyz (Kiro)** | Бюджет + цели + эволюция питомца от привычек | Иностранный продукт, не локальный офлайн-прототип под рамку компетенций РФ. |
| **FiPet** | Квесты 5 мин, рост питомца, Duolingo-петля | Подростки, квизы/батлы, внутриигровые покупки, лидерборды — против границ ТЗ. |
| **CapyFinance** | Питомец отражает учебные привычки, отчёты взрослому | HK/школы, облако, подписка, учёт вне игровой валюты. |
| **FinLet** | Игровая валюта, локально, без рекламы, PIN взрослого, питомец, цели | Дела по дому + ежедневный квиз; слабее связка план/факт трёх корзин и «безопасная ошибка». Есть сетевой чат. |
| **Sprout Saver / FamilyCents** | Три визуальные корзины, уроки, прогресс терпения | Семейный учёт вне чистой игровой экономики, аккаунты, подписки. У нас берём только UX корзин. |

### 3.2. Разрывы, которые можно превратить в преимущество

1. **Одна петля вместо трёх приложений.** Рынок режет продукт на «квиз», «копилку» и «тамагочи». ТЗ требует, чтобы одно решение меняло баланс, план/факт и питомца сразу — это и есть дифференциация, если сделать её видимой за 3 секунды на главном экране.
2. **Безопасная ошибка.** Конкуренты-питомцы наказывают пропуском. Мы: ошибка = понятная задача на следующий период, прогресс не обнуляется, без болезни/смерти.
3. **План vs факт как геймплей, не как Excel.** Почти никто в детском RU-сегменте не делает подтверждённый план и сравнение с фактом как ядро цикла.
4. **Задание ≠ тест.** ФиНЗнайка/FiPet выигрывают объёмом вопросов. Мы выигрываем мини-сценой: «в магазине две цены / цель через N периодов / непредвиденный расход».
5. **Офлайн + без аккаунта + только игровые монеты.** Западные pet+budget почти все в облаке; нам нужен локальный учебный цикл.
6. **Рамка компетенций и язык жюри.** Конкуренты говорят «навык копить»; жюри ждёт формулировки из рамки. Карта контента «тема → навык → сценарий → фраза ребёнку» — отдельный артефакт, не украшение.
7. **Демо-режим для эксперта.** У коммерческих приложений этого нет; на конкурсе это must. Сделать демо честным (тот же движок экономики, не читы), иначе оценка «техпроработки» просядет.
8. **Этика мотивации.** Не стыдить, не «питомец пострадает, если не купишь еду средствами вне игры». Это критерий 8.1 и прямое требование ТЗ к текстам.

### 3.3. Что не копировать

- Лидерборды, чаты, покупки за средства вне игры, рекламу, streak-death.
- Советы по бюджету конкретной семьи пользователя (нет исходных данных и не наша задача).
- ИИ ради галочки (в ТЗ не обязателен и требует доказательств пользы и контроля качества).
- Длинные правила и мелкий текст.

### 3.4. План разведки (фаза 0, до кода)

Пока не рисуем архитектуру «навсегда» и не пишем игровой движок. Цель фазы — таблица «украсть / отвергнуть / отличиться» с пруфами (скрины, формулировки стора, 3–5 экранов каждого).

| # | Действие | Зачем | Результат |
|---|----------|--------|-----------|
| R1 | Пройти/записать RuStore: Три Кота, игровая копилка, Tam Tam | Локальный UX и тон 7–11 | 10 скринов + заметки «что понятно за 10 секунд» |
| R2 | Разобрать Финзнайку 6+: типы заданий, награды, где нет последствий выбора | Почему квиз не закрывает ТЗ | 3 контрпримера мини-сцен для наших заданий |
| R3 | Пройти материалы: Открытый бюджет Москвы, fincult.info, рамка компетенций (если есть PDF у организатора) | Язык жюри и термины | Глоссарий 15 слов «как ребёнку / как в ТЗ» |
| R4 | Референс UX трёх корзин: Sprout Saver jars, экран баланса FinLet, бюджет Monyz (по видео/стору) | Главный экран и план бюджета | 1 wireframe трёх корзин + питомец |
| R5 | Собрать антипаттерны тамагочи (голод по реальному времени, болезнь) | Соответствие «без тревоги» | Правила состояний питомца (черновик формул) |
| R6 | Сверить Приложение А с матрицей 2.5 | Ничего не выпадет на промежуточной сдаче | Чеклист статусов «не начато» |

**Вопросы второму участнику (нужно спросить):** кто ведёт арт питомца; какой стек склонен выбрать (Kotlin / Flutter / RN) — решение после R4, не до; длина игрового периода (день/неделя/«кнопка демо»); есть ли доступ к рамке компетенций файлом.

## 4. Базовый MVP-план (конкурсный прототип)

Цель MVP: **закрыть Приложение А на физическом Android + минимум контента из п. 2.6**, без сервера, без ИИ, без iOS.

Предлагаемые срезы (после фазы 0):

1. **Экономический движок (без UI)** — баланс, план, факт, покупки, накопления, состояния, стадии, демо-тикер периода. Автотесты формул. Это сердце оценки 8.2.
2. **Контент как данные** — JSON/YAML заданий, товаров, целей, текстов обратной связи. Добавление 7-го задания без правки логики.
3. **Онбординг + кастом питомца** — 9 комбинаций (3×3 достаточно: тело/цвет/аксессуар).
4. **Главный экран** — все обязательные виджеты, крупные тач-цели ≥ 48 dp, текст ≥ 16 sp.
5. **Бюджет и магазин** — три корзины, остаток, две покупки разных типов, отказ при нехватке.
6. **Цель + копилка** — выбор из 3, пополнение, предупреждение при снятии.
7. **6 заданий / 3 темы** — каждое: сцена → выбор → последствие в экономике → 1–2 фразы «почему».
8. **Рост за 5 демо-периодов** — видимая смена стадии с объяснением.
9. **Родительский барьер + сброс тестового профиля.**
10. **Обвязка сдачи** — демо-режим, persist, APK, README, матрица требований, 3+ скрина, запасное видео.

Вне MVP хакатона: мультиплеер, облако, ИИ-наставник, игровые дела с подтверждением взрослого, планшет/ландшафт (плюс, не блокер), глубокая кастомизация. Вне игры экономика не выходит.

## 5. Продвинутый план (свой продукт после конкурса)

Не подменяет обязательное. Имеет смысл только если ядро «план–факт–питомец» уже честное.

**Продуктовая ставка:** остаться **бесплатной обучающей платформой** на вымышленных монетах и стать привычкой на 4–8 недель, которую взрослый понимает за одну минуту в защищённом разделе.

Возможные слои:

| Слой | Что добавляем | Зачем, если смотреть на конкурентов |
|------|----------------|-------------------------------------|
| Контент | Сезоны, непредвиденные расходы (разрешённый ТЗ кейс «лечение» как статья, не как травма), больше целей | Объём как у Финзнайки, но в механике решений |
| Семья | Опциональные игровые «дела» с подтверждением взрослого; награда — только монеты | Вовлечение семьи внутри той же учебной экономики |
| Прогресс | Безопасные серии привычек без наказания смертью; бейджи навыков рамки, не PvP | FiPet/Duolingo без лидербордов |
| Платформы | iOS, планшет, публикация в сторе по чек-листу готовности сборки | Тот же учебный клиент, та же валюта |
| Родитель | Расширенные темы «что обсудить», без удалённого управления игрой | Критерий «значимый взрослый» |
| Аналитика | Только opt-in взрослого, агрегированная, после юроценки 152-ФЗ | Поздний этап; в хакатоне не трогать |
| Бренд Москвы | Сюжеты на материалах Открытого бюджета / ДФ как просвещение | Локальный учебный тон |

ИИ в продвинутой версии — только если закрывает конкретный пробел (перефраз объяснения под возраст / генерация вариаций сцен) с ручной модерацией контента. Не как обязательный runtime.

## 6. Принцип приоритизации

```
Разведка (сейчас) → согласованные формулы экономики и тон питомца
→ SA по ядру цикла → код на Ivan_DevStand
→ демо Приложения А → контент до минимума 2.6
→ обвязка сдачи → (после финала) продвинутый слой
```

Код «сходу» по питомцу без экономики и без сверки с конкурентами даст красивый тамагочи, который **провалит 8.3** (три механики не связаны) и **8.4** (нет учебного выбора).
